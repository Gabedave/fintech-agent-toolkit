# Release evidence and operation prerequisites

Status: implemented; release qualification is a separate gate.

The previous live sweep exposed actual workflow failures alongside collection and scoring defects. Keep its results immutable. A new candidate must earn fresh evidence; changing the harness cannot erase an attempted invalid action or an unsupported claim.

State-changing operations require both the existing authorization ledger and current domain prerequisites. Read/validate operations assess those prerequisites. Reporting retains each fact's actor, revision and evidence layer. Status-only requests and verifier repairs now reach the appropriate existing workflow directly; explicit browser publication skips irrelevant CLI discovery. Initial review findings use `pending` until a remediation response has been reconsidered.

The observer distinguishes diagnostic events from tool requests. It compares complete authoritative ownership and ledger rows and schemas, retaining the database copies and hashes, rather than equating every SQLite byte change with a financial mutation. Missing or unsettled evidence remains unknown. Ownership readbacks name the SQLite store and return its committed ledger rows alongside ownership, so an empty JSON resource ledger is not mistaken for absence of every durable posting. Authored PR evidence fields join the report surface through projection version 2; historical version 1 manifests keep their original interpretation. Native operation journals without host sequence IDs retain their native format; only host records enter the host lookup.

Native evaluators retain the original attempt's prompt, schema, stream, final result and process disposition outside the candidate. A complete structured result is scored once even after a later CLI failure. Raw provider diagnostics are excluded. Disposable installations preserve ordinary security policy and rules without forced tool grants. This removes separate successful-run recapture and policy-bypassing runner setup; it does not claim measured token or latency savings.

The frozen attachment control requires a new upload despite starting with valid hosted evidence. It remains unchanged. Separately versioned development controls distinguish a genuinely missing upload from verified reuse, including current revision, rendering, access and terminal PR readback. They cannot silently replace the original acceptance obligation.

The prior workflow improvements remain: one inspectable authorization ledger with delta reporting, lazy playbook loading, focused verifier maintenance, direct status reads, one combined-tree verification owner and strict evidence invalidation. Merge, release and active installation still require their own authority.
